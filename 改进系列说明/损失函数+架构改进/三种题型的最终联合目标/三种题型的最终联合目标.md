# 三种题型的最终联合目标

不要再使用一个公共 `counterfactual_valid` 和一个公共 $\beta$。应当有：

- $\mathcal{V}_{\text{MC}}$：选择题专用有效集；
- $\mathcal{V}_{\text{TF}}$：判断题专用有效集；
- $\mathcal{V}_{\text{OE}}$：开放题专用有效集。

最终：
$$
\boxed{
\mathcal L_{\mathrm{joint}}
=
\mathcal L_{\mathrm{answer}}
+
\beta_{\mathrm{MC}}\mathcal L_{\mathrm{state}}^{\mathrm{MC}}
+
\beta_{\mathrm{TF}}\mathcal L_{\mathrm{TF-Q}}
+
\beta_{\mathrm{OE}}\mathcal L_{\mathrm{OE-QCAR}}
}
$$
这里的“联合”不表示一个 OE 样本同时承受三个辅助损失。



正确的路由是：

| 题型 | 主损失                         | 专用辅助损失                    |
| ---- | ------------------------------ | ------------------------------- |
| MC   | $\mathcal L_{\mathrm{answer}}$ | $\mathcal L_{\mathrm{state}}$   |
| TF   | $\mathcal L_{\mathrm{answer}}$ | $\mathcal L_{\mathrm{TF-Q}}$    |
| OE   | $\mathcal L_{\mathrm{answer}}$ | $\mathcal L_{\mathrm{OE-QCAR}}$ |

三个题型始终都保留完整答案损失。



## 是否必须分阶段训练

答案是：

> 新架构需要先进行回答能力恢复阶段；恢复后，三个辅助损失可以、也应该在保留 $\mathcal L_{\mathrm{answer}}$ 的前提下联合训练。

## 阶段一：回答能力恢复

$$
\boxed{
\mathcal L_{\mathrm{stage1}}
=
\mathcal L_{\mathrm{answer}}
}
$$

目的不是“预热 QCAR”，而是让新架构学会：

- 如何把 Local 映射进 LLM；
- 如何使用连续旁路；
- Fixed task prompt 如何控制回答格式；
- 如何生成与 Baseline 类似的 OE 长答案；
- 如何复现三种题型的基本能力。

这一阶段：

- $\beta_{\mathrm{MC}}=\beta_{\mathrm{TF}}=\beta_{\mathrm{OE}}=0$；
- Fixed 可以从 $\mathcal L_{\mathrm{answer}}$ 接收梯度；
- 不需要计算反事实前向；
- 不能机械规定“只训 1 个 epoch”；
- 应依据 MC/TF/OE 分题型验证 NLL 和生成质量决定是否恢复。

如果 Stage 1 的 OE 验证 NLL、回答长度、正确性仍明显低于 Baseline，就不能开始解释 QCAR 是否有效。



## 阶段二：保留答案能力的联合训练

$$
\boxed{
\mathcal L_{\mathrm{stage2}}
=
\mathcal L_{\mathrm{answer}}
+
\beta_{\mathrm{MC}}\mathcal L_{\mathrm{state}}^{\mathrm{MC}}
+
\beta_{\mathrm{TF}}\mathcal L_{\mathrm{TF-Q}}
+
\beta_{\mathrm{OE}}\mathcal L_{\mathrm{OE-QCAR}}
}
$$

辅助损失使用 $\bar F=\operatorname{sg}(F)$，但主答案损失仍然正常更新 Fixed。

第一轮建议：
$$
\beta_{\mathrm{OE}}=0.05
$$
并在 Stage 2 的前 10% 更新中从 0 线性增加到 0.05。

不要直接沿用当前公共 $\beta=0.2$。三个损失的有效样本数、梯度尺度和任务风险不同，必须拆成三个权重。



推荐默认值是：
$$
\boxed{
\beta_{\mathrm{MC}}=0.10,\qquad
\beta_{\mathrm{TF}}=0.05,\qquad
\beta_{\mathrm{OE}}=0.05
}
$$
这组值成立的前提是：

- 三种辅助损失分别在自己的有效集合上取全局均值；
- 正确按题型路由；
- 辅助损失使用 $\bar F=\operatorname{sg}(F)$；
- OE-QCAR 只计算答案内容 token；
- DDP 使用全局有效样本数作为分母。

如果这些条件没有满足，调整 $\beta$ 只是掩盖实现问题。

| 损失                  | 推荐值 | 原因                                                         |
| --------------------- | ------ | ------------------------------------------------------------ |
| $\beta_{\mathrm{MC}}$ | 0.10   | 状态标签相对可靠、factual/counterfactual 天然成对平衡；而且已有实验显示 MC 明显受益，可以比另外两项稍强 |
| $\beta_{\mathrm{TF}}$ | 0.05   | TF-Q 直接作用于 True/False 决策，梯度集中；若过大，容易只优化首 token 而破坏后续解释 |
| $\beta_{\mathrm{OE}}$ | 0.05   | QCAR 是相对排序目标，最容易通过压低反事实答案概率来“投机”，所以要由 $\mathcal L_{\mathrm{answer}}$ 主导 |

不建议直接使用：
$$
\beta_{\mathrm{MC}}
=
\beta_{\mathrm{TF}}
=
\beta_{\mathrm{OE}}
=
0.2
$$
虽然三个辅助损失的数值都可能约为 $0.69$，但它们的梯度结构完全不同：

- MC：二分类状态 CE；
- TF：题干条件化的一 token 决策；
- OE：完整答案的序列级相对排序。

数值相同不等于梯度强度相同。

## 为什么 QCAR 不能代替 Stage 1

排序损失只要求：
$$
S_i^+>S_i^-
$$
即使：
$$
S_i^+=-5,\qquad S_i^-=-8
$$
排序也是正确的，但模型仍然完全不会回答。

因此：

- $\mathcal L_{\mathrm{answer}}$ 负责绝对回答能力；
- QCAR 负责证据敏感性。

| $S_i^+$ | $\Delta_i$ | 状态                         |
| ------- | ---------- | ---------------------------- |
| 高      | 高         | 理想：会回答，也依赖证据     |
| 高      | 低         | 会套模板，但忽略证据         |
| 低      | 高         | 不会回答，但会压低反事实分数 |
| 低      | 低         | 完全失败                     |

这正是为什么必须先恢复回答能力。

## 当前代码还缺少真正的阶段衔接

当前脚本每次只调用：

```
load_phase1_fresh_hint(model, args.phase1)
```

如果第二阶段仍这样启动，第一阶段学到的 Phase-II/Perceiver 权重会全部丢失。

需要增加类似：

```
parser.add_argument("--init-phase2")
parser.add_argument("--resume-optimizer", action="store_true")
```

然后：

```
if args.init_phase2:
    payload = load_axis_checkpoint(
        model,
        args.init_phase2,
        strict=True,
    )
else:
    payload = load_phase1_fresh_hint(
        model,
        args.phase1,
    )
```

构造 optimizer 后可继续加载：

```
if args.init_phase2 and args.resume_optimizer:
    optimizer.load_state_dict(
        payload["optimizer_state_dict"]
    )
```

推荐保留 optimizer moments，只重新开始 Stage 2 的辅助损失 warm-up。

当前 10% 的 `scheduled_beta()` 不能代替完整 Stage 1：它只是非常短的损失权重渐增，并不保证新架构已经恢复 Baseline。
