# TF

- 沿用符号：
  - $X_i$：第 $i$ 条原始完整时间序列；
  - $X_i^-$：完整一致反事实时间序列；
  - $I_i=[s_i,e_i)$：目标窗口区间；
  - $W_i$：从 $X_i[I_i]$ 格式化得到的 Window 文本；
  - $W_i^-$：从 $X_i^-[I_i]$ 格式化得到的反事实 Window；
  - $L_i$：由冻结时间序列编码器 $E_0$ 从 $X_i$ 得到的 Local Hint；
  - $L_i^-$：从 $X_i^-$ 得到的反事实 Local Hint；
  - $F$：Fixed task-prior Hint；
  - $Q_i$：原始问答问题；
  - $Y_i$：完整参考答案；
  - $z_i\in\{0,1\}$：`has_anomaly`，0 为正常，1 为异常；
  - $Q^z$：统一的状态分类问题。





推荐采用“先恢复回答能力，再联合加入辅助损失”的训练方式。不是把多个损失完全拆开依次训练，而是：

1. 阶段 1 只训练 $\mathcal{L}_{\text{answer}}$，让新架构复现 Baseline；
2. 阶段二继续保留 $\mathcal{L}_{\text{answer}}$，同时以较小权重加入 $\mathcal{L}_{\text{state}}$ 和 $\mathcal{L}_{\text{TF-Q}}$

也就是：
$$
\boxed{
\text{Answer-only 预训练}
\quad\longrightarrow\quad
\text{Answer + State + TF-Q 联合训练}
}
$$
绝对不建议：
$$
\text{先 Answer}
\rightarrow
\text{再只训练 State}
\rightarrow
\text{再只训练 TF-Q}
$$
因为后两个阶段会遗忘前面已经学会的答案生成能力。



另外，重新核对代码后发现一个非常关键的问题：

> 目前代码中的 $\mathcal L_{\text{state}}$ 并没有只应用于选择题，而是应用于所有具有合法反事实的 MC、TF、OE 样本。

当前实现只有：

```
valid = counterfactual_valid.bool()
```

并没有：

```
question_type == "multiple_choice"
```

过滤，参见当前 state loss 的样本选择。这很可能是 TF/OE 下降的重要原因之一。后续必须显式按题型划分监督。



## $\mathcal{L}_{\text{TF-Q}}$ 究竟要解决什么问题？

当前状态损失 $\mathcal{L}_{\text{state}}$ 使用 
$$
\begin{cases}
(Q^z,L_i,W_i,F) \longrightarrow z_i \\
(Q^z,L_i^-,W_i^-,F) \longrightarrow 1-z_i
\end{cases}
$$
它回答的是：**当前窗口正常还是异常？**但判断题真正回答的是：**原始题干 $Q_i$ 中的陈述是真还是假？**



所以判断题所需的变量不是 $z_i$，而是：
$$
t_i = \begin{cases}
0,\quad & Y_i \text{以 False 开头} \\
1,\quad & Y_i \text{以 True 开头}
\end{cases}
$$
举一个最简单的例子：两个窗口都是异常的：$z_1 = z_2 = 1$，但判断题可以是：

- $Q_1$：这个窗口存在异常，答案 True；
- $Q_2$：这个窗口不存在异常，答案 False

也就是说，相同的 $z=1$，根据题干表述不同，可以得到不同的 True/False。



当前缺失的是：
$$
(Q_i , z_i, \text{evidence}) \longrightarrow t_i
$$
就是：**判断题答案的 True/False 和 `has_anomaly` 的 True/False 它不是同一个东西。**



## 为什么原始答案损失还不够？

原始判断题答案通常是：

> False. The time series window ... There is a significant anomaly ...



完整答案可能包含上百个 token。原始答案损失是：
$$
\mathcal{L}_{\text{answer},i} - -\frac{1}{|Y_i|} \sum_{k=1}^{|Y_i|} \log P_{\Theta} (Y_{i,k} \mid Y_{i,<k},Q_i,L_i,W_i,F)
$$
假设答案有 175 个 token，那么 True/False 对整体 loss 的直接贡献大约只有：
$$
\frac1{175}\approx0.57\%
$$
其余绝大多数损失来自：

- 句式组织；
- 位置、数值和趋势描述；
- 常见解释模板；
- 语法和流畅性。

所以模型可能写出一段流畅的解释，却把最前面的 True/False 判断错了。

$\mathcal L_{\text{TF-Q}}$ 的作用就是：

> 在原始判断题 $Q_i$ 下，把 True/False 决策单独拿出来，给予明确的二分类监督。

它不是替代完整答案损失，而是补充完整答案损失中被长文本稀释的判断信号。



## 这个损失的核心输入是什么？

状态损失 $\mathcal{L}_{\text{state}}$ 使用统一问题 $Q^z$，但是 $\mathcal{L}_{\text{TF-Q}}$ 必须使用 **原始判断题 $Q_i$**。



**1. Factual 输入**
$$
\mathcal{P}_i^{TF,+} = \text{Prompt}(Q_i,L_i,W_i ,\text{sg}(F))
$$
**2. 反事实输入**
$$
\mathcal{P}_i^{TF,-}= \text{Prompt}(Q_i,L_i^-,W_i^- ,\text{sg}(F))
$$
其中：$\text{sg}(F)$ 表示 Fixed Hint 参与前向计算，但不接受该辅助损失的梯度。



注意两个输入：

- 原始问题 $Q_i$ 完全相同；
- Fixed Hint $F$ 完全相同；
- 只有证据 $L,W$ 发生变化。

因此模型必须根据证据变化调整 True/False，而不能通过问题模板或 Fixed Hint 单独完成任务。



## 如何从原始判断题得到 True/False 概率？

### 1. 构造与推理一致的 prompt

当前 AXIS 的生成结果通常以 `Answer:True.` 或 `Answer:False` 开始。

因此可以构造：

```text
You are an expert time series analyst...

### Time Series Data
...

### Contextual Hints
...

### Question
True or False: ...

Answer:
```



然后读取冻结 LLM 在 `Answer:` 后面预测下一个 token 时，对 `True` 和 `False` 的 logits。



### 2. 定义 verbalizer

定义：

- $v_0 = \texttt{" False"}$；
- $v_1 = \texttt{" True"}$；

目标仍采用：
$$
t_i = \begin{cases}
0,\quad & Y_i \text{以 False 开头} \\
1,\quad & Y_i \text{以 True 开头}
\end{cases}
$$


对于事实输入：

设冻结 LLM 在 `Answer:` 后的最后一个 hidden state 为：$h_i^+ \in \mathbb{R}^{d_{\text{LLM}}}$

LM head 中对应的 False 和 True token 的权重分别为：
$$
u_{\text{False}}, u_{\text{True}} \in \mathbb{R}^{d_{\text{LLM}}}
$$
则 factual logits 为：
$$
s_i^+
=
\begin{bmatrix}
u_{\text{False}}^\top h_i^+\\
u_{\text{True}}^\top h_i^+
\end{bmatrix}
\in\mathbb R^2
$$
概率为：
$$
p_i^+
=
\operatorname{Softmax}(s_i^+)
$$
同理，反事实输入得到：
$$
s_i^-=
\begin{bmatrix}
u_{\text{False}}^\top h_i^-\\
u_{\text{True}}^\top h_i^-
\end{bmatrix} \\
p_i^- = \text{Softmax}(s_i^-)
$$
这里不需要新增一个可训练二分类头，而是直接使用冻结 LLM 原本的 LM head。这样训练目标与最终生成 True/False 的方式一致。



## 反事实判断题答案 $t_i^-$ 应该怎么构造？

这是整个方法最重要、也是最容易出错的地方。不能对所有判断题都直接使用：
$$
t_i^- = 1- t_i
$$
只有当判断题是“纯状态命题”时，才能这样做。



#### 1. 定义题干极性 $a_i$

对于纯状态判断题，定义：
$$
a_i = \begin{cases}
1,\quad &Q_i \text{声称窗口存在异常}\\
0,\quad & Q_i \text{生成窗口正常或不存在异常}
\end{cases}
$$
例如：



| 题干                                                  | $a_i$ |
| ----------------------------------------------------- | ----- |
| “There is evidence of anomalous behavior.”            | 1     |
| “The window contains an anomaly.”                     | 1     |
| “No anomalous pattern is present.”                    | 0     |
| “The window is free from anomalies.”                  | 0     |
| “The pattern is consistent with normal fluctuations.” | 0     |

$z_i\in\{0,1\}$：`has_anomaly`，0 为正常，1 为异常。对于 factual 窗口：
$$
t_i=\mathbf1[z_i=a_i]
$$
对于反事实窗口：
$$
z_i^-=1-z_i
$$
因此：
$$
t_i^-
=
\mathbf1[z_i^-=a_i]
=
\mathbf1[1-z_i=a_i]
=
1-t_i
$$
所以，只有在纯状态命题中，状态翻转才严格推出判断题答案翻转。



| 窗口状态 $z_i$ | 题干声称 $a_i$ | 判断题答案 $t_i$ |
| -------------- | -------------- | ---------------- |
| 异常 1         | 存在异常 1     | True             |
| 异常 1         | 不存在异常 0   | False            |
| 正常 0         | 存在异常 1     | False            |
| 正常 0         | 不存在异常 0   | True             |



### 哪些判断题不能直接使用 $t_i^- = 1-t_i$？

例如：

> True or False: The anomaly is a downward spike near the center of the window.

这不是纯状态命题，它同时涉及：
$$
A_i=
(\text{type=spike},
\text{direction=downward},
\text{location=center})
$$
假设 factual 窗口：

- 确实异常；
- 但异常是 upward spike；
- 因此原答案是 False。

删除异常后，反事实窗口正常。题干中的“downward spike”仍然是 False：
$$
t_i=0,\qquad t_i^-=0
$$
如果机械使用：
$$
t_i^-=1-t_i=1
$$
就产生错误监督。

再例如：

> True or False: The anomaly occurs after step 20.

原异常发生在 step 10，所以 factual 是 False；删除异常后仍然是 False。

因此，第一版实现中，建议只把以下问题纳入反事实 TF-Q：

- 是否存在异常；
- 是否没有异常；
- 是否符合正常行为；
- 是否包含异常行为；
- 是否 free from anomalies。

暂时排除：

- upward/downward；
- spike/drop/shift/drift；
- 中心、边界等具体位置；
- 具体数值、幅度；
- 持续时间；
- 特定异常类型。

这不是方法能力不足，而是在保证监督的正确性。第一版应优先追求高精度，而不是覆盖所有判断题。



## 如何自动判断一个 TF 样本是否可用？

定义可靠 TF 反事实集合：
$$
\mathcal V_{\text{TF}}
=
\left\{
i\mid
q_i=\text{true\_false},
r_i^{\text{format}}=1,
r_i^{\text{predicate}}=1,
r_i^{\text{consistent}}=1,
r_i^{\text{cf}}=1
\right\}
$$
其中：

### 1. 答案格式有效

$$
r_i^{\text{format}}=
\mathbf1[
Y_i\text{ 以 True 或 False 开头}
]
$$

代码：

```
def parse_tf_target(answer: str):
    text = answer.strip().lower()

    if text.startswith("true"):
        return 1

    if text.startswith("false"):
        return 0

    return None
```

你的数据中 20204 条判断题里有 20200 条满足该格式，只有 4 条需要跳过。

### 2. 是纯状态命题

$$
r_i^{\text{predicate}}=
\mathbf1[
Q_i\text{ 只判断异常存在性或正常性}
]
$$

建议先离线构造，而不是训练过程中临时判断。

简化的高精度实现：

```
ATTRIBUTE_WORDS = {
    "upward",
    "downward",
    "spike",
    "drop",
    "shift",
    "drift",
    "amplitude",
    "periodic",
    "center",
    "boundary",
    "sustained",
    "consecutive",
}

NEGATIVE_STATE_PATTERNS = [
    "no anomalous",
    "no anomaly",
    "absence of anomal",
    "free from anomal",
    "does not contain any anomal",
    "consistent with normal",
    "normal fluctuations",
]

POSITIVE_STATE_PATTERNS = [
    "contains an anomaly",
    "contains anomalies",
    "presence of an anomaly",
    "evidence of anomalous behavior",
    "indicating an anomaly",
]


def parse_state_predicate(question: str):
    q = question.lower()

    # 第一版宁可少用，不要把属性题错误当成纯状态题
    if any(word in q for word in ATTRIBUTE_WORDS):
        return None

    if any(pattern in q for pattern in NEGATIVE_STATE_PATTERNS):
        return 0

    if any(pattern in q for pattern in POSITIVE_STATE_PATTERNS):
        return 1

    return None
```

这只是第一版骨架。你应该：

1. 用它筛选全部 TF；
2. 随机抽取 200 条；
3. 人工检查；
4. 目标是精度达到 98% 以上；
5. 再逐步扩充模板。

### 3. 参考答案与 `has_anomaly` 一致

已得到：

- 题干极性 $a_i$；
- 参考 True/False 标签 $t_i$；
- `has_anomaly` 标签 $z_i$。

定义：
$$
r_i^{\text{consistent}}
=
\mathbf1[
t_i=\mathbf1[z_i=a_i]
]
$$
代码：

```
expected_tf_target = int(state_target == predicate_polarity)
consistent = tf_target == expected_tf_target
```

例如：

- $z_i=1$；
- 题干声称正常，$a_i=0$；
- 参考答案 False，$t_i=0$。

则：
$$
\mathbf1[z_i=a_i]=\mathbf1[1=0]=0=t_i
$$
样本一致，可以使用。

而你数据中的矛盾样本：

- $z_i=0$；
- 题干声称没有异常，$a_i=0$；
- 参考答案 False，$t_i=0$。

理论上：
$$
\mathbf1[z_i=a_i]=\mathbf1[0=0]=1
$$
但参考答案是 0，因此：
$$
r_i^{\text{consistent}}=0
$$
该样本不得用于反事实 TF-Q。

### 4. 反事实有效

$$
r_i^{\text{cf}}
=
\mathbf1[
X_i^-\text{ 确实对应状态 }1-z_i
]
$$

不能只依赖“反事实文件存在”，还应通过你前面设计的：

- 数值范围；
- seam；
- donor；
- 状态翻转有效性检查。

最终：
$$
r_i^{\text{TF}}
=
r_i^{\text{format}}
r_i^{\text{predicate}}
r_i^{\text{consistent}}
r_i^{\text{cf}}
$$


## $\mathcal{L}_{\text{TF-Q}}$ 的完整公式

对于 $i \in \mathcal{V}_{\text{TF}}$

- factual 目标为 $t_i$
- counterfactual 目标为 $t_i^- = 1 - t_i$

定义：

- factual true/ False logits：$s_{\Theta}(Q_i, L_i, W_i, \text{sg}(F)) \in \mathbb{R}^2$
- counterfactual True/False Logits：$s_{\Theta}(Q_i, L_i^-,W_i^-, \text{sg}(F)) \in \mathbb{R}^2$



最终：
$$
\boxed{
\mathcal L_{\text{TF-Q}}
=
\frac1{2|\mathcal V_{\text{TF}}|}
\sum_{i\in\mathcal V_{\text{TF}}}
\left[
\operatorname{CE}
\left(
s_\Theta(Q_i,L_i,W_i,\operatorname{sg}(F)),
t_i
\right)
+
\operatorname{CE}
\left(
s_\Theta(Q_i,L_i^-,W_i^-,\operatorname{sg}(F)),
1-t_i
\right)
\right]
}
$$
它表达的是：

> 同一个原始判断题，在 factual 和 counterfactual evidence 下，应该得到相反的 True/False 答案。

注意：这是“问题条件下”的相反答案，不是固定状态问题下的 normal/anomalous。





### $\mathcal{L}_{\text{TF-Q}}$ 与 $\mathcal{L}_{\text{state}}$ 的本质区别



| 项目                   | (\mathcal L_{\text{state}}) | (\mathcal L_{\text{TF-Q}}) |
| ---------------------- | --------------------------- | -------------------------- |
| 使用问题               | 固定 (Q^z)                  | 原始判断题 (Q_i)           |
| 输出                   | normal/anomalous            | False/True                 |
| 目标                   | (z_i)                       | (t_i)                      |
| 是否理解否定           | 不需要                      | 需要                       |
| 是否与最终 TF 输出一致 | 间接                        | 直接                       |
| 推荐题型               | 选择题辅助                  | 判断题                     |
| Fixed 是否接收梯度     | 否                          | 否                         |





## 代码层面如何实现 True/False logits？

### 1. 选择 verbalizer token

顺序建议固定为：

```
[False, True]
```

这样 target 0/1 与答案标签一致。

```
from dataclasses import dataclass


@dataclass(frozen=True)
class TFVerbalizers:
    false_text: str
    true_text: str
    false_id: int
    true_id: int


def select_tf_verbalizers(tokenizer) -> TFVerbalizers:
    candidates = [
        (" False", " True"),
        ("False", "True"),
    ]

    for false_text, true_text in candidates:
        false_ids = tokenizer.encode(
            false_text,
            add_special_tokens=False,
        )
        true_ids = tokenizer.encode(
            true_text,
            add_special_tokens=False,
        )

        if (
            len(false_ids) == 1
            and len(true_ids) == 1
            and false_ids[0] != true_ids[0]
        ):
            return TFVerbalizers(
                false_text=false_text,
                true_text=true_text,
                false_id=int(false_ids[0]),
                true_id=int(true_ids[0]),
            )

    raise RuntimeError(
        "True/False cannot be represented by distinct single tokens"
    )
```

### 2. 构造 TF prompt

新增：

```
def generate_tf_input_ids(
    self,
    questions,
    time_series,
    start_indices,
    end_indices,
    window_values_override=None,
):
    prompts = []

    for index, question in enumerate(questions):
        values = (
            time_series[index, start_indices[index]:end_indices[index]]
            if window_values_override is None
            else window_values_override[index]
        )

        prompt = format_axis_question_prompt(
            question=question,
            start_index=start_indices[index],
            end_index=end_indices[index],
            window_values=values,
            num_fixed_tokens=self.num_fixed_tokens,
            include_local=True,
            include_window=True,
            include_fixed=True,
        ).rstrip()

        prompts.append(prompt + "\n\nAnswer:")

    previous_padding_side = self.tokenizer.padding_side

    try:
        self.tokenizer.padding_side = "right"
        encoded = self.tokenizer(
            prompts,
            return_tensors="pt",
            padding=True,
            truncation=True,
            add_special_tokens=True,
        )
    finally:
        self.tokenizer.padding_side = previous_padding_side

    return encoded["input_ids"], encoded["attention_mask"]
```

这里绝对不能把 gold answer 放入 prompt，否则模型可以直接从 gold answer 读取 True/False，而不需要看证据。

### 3. 新增 `tf_logits()`

它可以直接仿照当前 `state_logits()`：

```
def tf_logits(
    self,
    local_embeddings,
    time_series,
    questions,
    start_indices,
    end_indices,
    window_values_override,
    false_id,
    true_id,
    *,
    fixed_hint_frozen=True,
):
    input_ids, attention_mask = self.generate_tf_input_ids(
        questions=questions,
        time_series=time_series,
        start_indices=start_indices,
        end_indices=end_indices,
        window_values_override=window_values_override,
    )

    device = self.get_device()
    input_ids = input_ids.to(device)
    attention_mask = attention_mask.to(device)

    input_embeddings = self.get_hint_embeddings(
        input_ids=input_ids,
        local_embeddings=local_embeddings,
        start_indices=start_indices,
        end_indices=end_indices,
        detach_fixed_hint=fixed_hint_frozen,
    )

    hidden = self.model.model(
        inputs_embeds=input_embeddings,
        attention_mask=attention_mask,
        use_cache=False,
        return_dict=True,
    ).last_hidden_state

    last_index = attention_mask.sum(dim=1) - 1
    batch_index = torch.arange(
        hidden.shape[0],
        device=device,
    )

    final_hidden = hidden[batch_index, last_index]

    # 顺序：[False, True]
    label_ids = torch.tensor(
        [false_id, true_id],
        device=device,
    )

    selected_weight = self.model.lm_head.weight[label_ids]

    selected_bias = None
    if self.model.lm_head.bias is not None:
        selected_bias = self.model.lm_head.bias[label_ids]

    logits = F.linear(
        final_hidden,
        selected_weight,
        bias=selected_bias,
    )

    return logits
```

输出形状：
$$
[B_{\text{TF}},2]
$$
第 0 列为 False logit，第 1 列为 True logit。

```
    [
        time_series[tf_valid],
        counterfactual_time_series[tf_valid],
    ],
    dim=0,
)

tf_questions = (
    [questions[index] for index in selected]
    + [questions[index] for index in selected]
)

tf_starts = (
    [start_indices[index] for index in selected]
    + [start_indices[index] for index in selected]
)

tf_ends = (
    [end_indices[index] for index in selected]
    + [end_indices[index] for index in selected]
)

tf_windows = (
    [positive_window_values[index] for index in selected]
    + [counterfactual_window_values[index] for index in selected]
)

factual_targets = tf_targets[tf_valid]

paired_targets = torch.cat(
    [
        factual_targets,
        1 - factual_targets,
    ],
    dim=0,
)

logits = self.tf_logits(
    local_embeddings=tf_local,
    time_series=tf_time,
    questions=tf_questions,
    start_indices=tf_starts,
    end_indices=tf_ends,
    window_values_override=tf_windows,
    false_id=false_id,
    true_id=true_id,
    fixed_hint_frozen=True,
)

tf_q_loss = F.cross_entropy(
    logits.float(),
    paired_targets.long(),
)
```

这只需要一次冻结 LLM forward，就能同时处理 factual 和 counterfactual。

### 如果 True/False 不是单 token 怎么办？

不要把 True/False 强行加入 tokenizer。

可以对完整候选前缀打分：
$$
V_0=\texttt{" False."}
$$
定义候选序列分数：
$$
S(V_c\mid\mathcal P)
=
\frac1{|V_c|}
\sum_{k=1}^{|V_c|}
\log
P_\Theta
\left(
V_{c,k}
\mid
\mathcal P,V_{c,<k}
\right)
$$
然后：
$$
s_i=
\begin{bmatrix}
S(V_0\mid\mathcal P_i)\\
S(V_1\mid\mathcal P_i)
\end{bmatrix}
$$
再做二分类交叉熵。

不过 Qwen tokenizer 大概率能把 `" True"`、`" False"` 各自编码成单 token。第一步应先打印并确认：

```
print(tokenizer.encode(" True", add_special_tokens=False))
print(tokenizer.encode(" False", add_special_tokens=False))
```



### 正式训练前必须做一次“读取位置校准”

由于当前 AXIS 的训练序列中包含：

```
Answer: {answer}
```

而推理是从 question prompt 直接生成，所以必须确认：

> 在我们构造的 `...\n\nAnswer:` 后读取 True/False logits，与模型真实生成答案的 True/False 一致。

不训练任何参数，直接在 baseline validation TF 上计算：

1. `tf_logits().argmax()`；
2. 实际生成结果开头的 True/False；
3. 二者的一致率。

如果一致率很高，说明读取位置正确。

如果一致率明显偏低，就使用完整候选序列：

```
Answer: True.
Answer: False.
```

做 sequence ranking，而不是单 token logits。

这一校准很重要，否则可能优化了一个与真实生成位置不一致的隐藏状态。
