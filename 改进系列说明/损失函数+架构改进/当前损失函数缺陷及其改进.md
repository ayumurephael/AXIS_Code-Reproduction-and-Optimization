# 最重要的已确认问题：实现与设计文档不一致

这是我认为当前首先必须修正的问题。

你的设计文档把状态分支写成：
$$
C_i^+=(W_i,L_i,\bar F),
\qquad
C_i^-=(W_i^-,L_i^-,\bar F)
$$
其中 $\bar F$ 应当冻结。设计意图是：

> 状态损失只能训练证据路径，而不能借助 Fixed/task prompt 改变冻结 LLM 的全局行为模式。

但实际训练代码调用的是：

```
self.state_logits(
    ...,
    fixed_hint_frozen=False,
)
```

即状态损失会反向传播到 task prompt。参见状态分支实现。同时 task prompt 被加入优化器，并设置了非零学习率，参见优化器参数组。

## 这为什么严重？

你真正希望的是：
$$
\nabla_{\theta_L}\mathcal L_{\text{state}}\neq0,
\qquad
\nabla_{\theta_F}\mathcal L_{\text{state}}=0
$$
但当前实现实际上允许：
$$
\nabla_{\theta_L}\mathcal L_{\text{state}}\neq0,
\qquad
\nabla_{\theta_F}\mathcal L_{\text{state}}\neq0
$$
其中：

- $\theta_L$：Local Hint/prototype/continuous 分支参数；
- $\theta_F$：直接 task prompt 参数。

Fixed/task prompt 虽然对所有样本相同，不能单独记住每个样本的类别，但它可以成为一个非常强的“模式控制器”：

- 在状态任务中，把冻结 LLM 推向“一位数字分类器”模式；
- 在原始回答任务中，又要求同一组 prompt 帮助模型生成较长、完整、有解释性的答案。

这两个梯度可能在同一 task prompt 上冲突。

因此当前模型可能学到的是：

> “看到这类辅助问题时，怎样让 LLM 快速输出类别。”

而不是：

> “怎样让 Local/Window 中的数值证据更好地进入自然语言解释。”

## 必须先做的修改

状态损失分支应改为：

```
state_logits_pos = model.state_logits(
    ...,
    fixed_hint_frozen=True,
)

state_logits_neg = model.state_logits(
    ...,
    fixed_hint_frozen=True,
)
```

并写三个梯度测试：

```
# 只反传 state loss
state_loss.backward()

assert task_prompt_embeddings.grad is None \
    or task_prompt_embeddings.grad.abs().max() == 0

assert local_continuous_parameters.grad is not None
assert prototype_attention_parameters.grad is not None
```

还要验证：

```
# 只反传 answer loss
answer_loss.backward()

assert task_prompt_embeddings.grad is not None
```

最终原则是：

| 损失                         | Local/prototype | Window adapter | Task prompt |
| ---------------------------- | --------------- | -------------- | ----------- |
| $\mathcal L_{\text{answer}}$ | 更新            | 更新           | 更新        |
| $\mathcal L_{\text{state}}$  | 更新            | 更新           | **冻结**    |



# 训练参数确实有问题，但不是唯一问题

新模型约 230.7M 可训练参数，其中：

- continuous：约 27.5M；
- prototype attention：约 203.0M，占约 88%；
- task prompt：约 0.108M。

而占 88% 的 prototype/attention 参数使用：
$$
\mathrm{LR}=2\times10^{-5}
$$
baseline 对 Hint Tuner 使用：
$$
\mathrm{LR}=1\times10^{-4}
$$
即最主要参数组的学习率只有 baseline 的五分之一。同时模型是新初始化架构，且验证 NLL 从：
$$
0.9836\rightarrow0.9491\rightarrow0.9287
$$
仍在持续下降，没有出现平台期。

所以，当前结果中存在一个很强的混杂因素：

> 新模型很可能还没有把原始答案生成能力学回来，就已经同时承担 state loss 和架构变化。

## 推荐训练顺序

| 参数组              | 建议起点         |
| ------------------- | ---------------- |
| prototype/attention | $1\times10^{-4}$ |
| continuous/gate     | $5\times10^{-5}$ |
| direct task prompt  | $5\times10^{-5}$ |



如果能够 warm-start：

- 加载 baseline 中兼容的 prototype/attention 参数；
- direct task prompt 初始化为 baseline Fixed processor 的输出；
- continuous fusion 使用上述 prototype-preserving 初始化。
